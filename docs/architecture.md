# Карта связей

## Обвязки разработчиков

`coordinator ↔ GitHub Issue ↔ arina-storage | filipp-infra | dima-gateway`

Один Issue — один получатель и один ограниченный запрос. Участник вручную запускает свою обвязку; она читает адресованный запрос и отвечает в том же Issue. Между компьютерами не открываются порты и не передаются ключи. Общий skill описывает процесс, а не сетевой транспорт.

Кодовые результаты остаются в PR исходного репозитория. Настоящая личность подтверждается автором GitHub и человеческим разрешением, не текстом `from`. При другой обвязке используется тот же протокол и проверенная локальная копия инструкций.

## Компоненты продукта

React B → browser API gateway → runner / storage — схема областей проверки, **не утверждение о текущем согласованном маршруте или транспорте**. Точные вызовы, форматы и совместимые версии берутся из продуктовых контрактов на конкретном SHA. Они не определяются протоколом обмена агентов.

| Граница | Кто должен подтвердить |
|---|---|
| React B ↔ gateway | владелец B и Дима |
| gateway ↔ runner | Дима и установленный владелец runner |
| gateway/runner ↔ storage | фактический потребитель и Арина |
| manifest/config/стенд | Филипп и владельцы включённых компонентов |

В этой версии владелец runner и актуальная совместимая сборка не установлены. Профили не перераспределяют обязанности, статусы или сроки YouGile.

# Подключение Арины, Филиппа и Димы

## 1. Доступ и две отдельные папки

Репозиторий приватный. Катя выдаёт доступ по подтверждённому GitHub login; этот пакет сам не отправляет приглашения. Пользуйтесь собственной авторизацией GitHub, не присылайте друг другу токены.

Проверка доступа: открыть репозиторий в GitHub и прочитать README. Если коннектор не видит новый приватный репозиторий, проверьте выбранный аккаунт и список доступных ему репозиториев в настройках подключения. При уже разрешённом доступе допустим собственный Git/CLI; иначе вернуть blocked. Не расширяйте права и не создавайте новые ключи молча. Для обмена нужен доступ к Issues и возможность комментировать; административные права участникам для этого не требуются.

Клонируйте обвязку в отдельную папку рядом с кодом продукта. Не кладите копию CoreTeams внутрь обвязки или другого checkout.

```text
git clone https://github.com/pokatyusha/coreteams-harness.git
cd coreteams-harness
git rev-parse HEAD
python scripts/validate.py
python -m unittest discover -s tests -v
```

Третий шаг даёт SHA обвязки. Сохраните его в локальной привязке и запросе. Обновляйте копию явно в начале согласованной работы; новый HEAD не должен молча менять инструкции уже принятой задачи. Сначала `git status`, затем fetch и просмотр отличий; не сбрасывайте dirty файлы.

## 2. Выбор профиля и привязка к коду

Арина — `arina-storage`; Филипп — `filipp-infra`; Дима — `dima-gateway`.

Скопируйте `templates/local-binding.example.json` в `.local/binding.json`, создав `.local` вручную. Заполните свой GitHub login, абсолютный путь к локальному коду, repository/branch/полный SHA и согласованные пути. `agent_id` выбирается человеком. Путь и файл binding остаются локальными, `.local` исключён из Git. До привязки ветки/путей допустим только connection_check, не работа с продуктом.

```text
python scripts/validate.py --binding .local/binding.json
```

Формат не заменяет проверку `git remote -v` и `git rev-parse HEAD` в исходном checkout. При несовпадении репозитория/SHA или scope остановитесь. Личная ветка участника не становится общей совместимой версией автоматически.

## 3. Подключение к своей обвязке

Откройте этот локальный репозиторий отдельным проектом/рабочей папкой в своём агенте. Для Codex вход — AGENTS.md и repo-local `.agents/skills`; для Claude вход — CLAUDE.md. Если ваша среда не подхватывает файлы автоматически, явно попросите прочитать их по локальному пути.

Если работаете из другой личной обвязки, добавьте в её существующие инструкции **ссылку на проверенную локальную папку**, ID профиля и закреплённый SHA. Не заменяйте целиком AGENTS.md/CLAUDE.md и не копируйте инструкции в несколько конкурирующих мест. Удалённый URL skill сам по себе не устанавливает skill. Не нужно глобально устанавливать его поверх личных навыков.

Стартовый запрос (замените ID, SHA, URL; не оставляйте угловые скобки):

```text
Прочитай AGENTS.md, registry.json, docs/exchange.md и профиль <мой профиль> из локальной coreteams-harness на SHA <полный SHA>. Используй .local/binding.json. Один ручной проход по Issue <URL> для agent_id <мой ID>. Проверь фактического автора и полномочия. Разрешаю прочитать запрос и отправить accepted/blocked и результат проверки связи в этот Issue. Продуктовый код и тесты не запускать. Без фоновых проверок, вложенных агентов, deploy и слияний. После ответа остановись.
```

Для выполнения продуктового задания человек отдельно задаёт scope и разрешения; connection_check их не выдаёт.

## 4. Проверка связи

- Катя создаёт адресованный connection_check с реальным harness_sha и уникальным request_id.
- Участник вручную запускает обвязку указанным запросом.
- Обвязка проверяет адрес/автора, отвечает accepted или blocked и возвращает completed с версией инструкций, ID профиля и ограничениями. Проверки продукта отмечает NOT_RUN.
- Катя читает ответ и подтверждает verified. Только после этого связь считается проверенной. Регистрация профиля, GitHub-доступ и подтверждённая связь — три разные отметки.

В этой поставке live-проверка с участниками **NOT_RUN**, все три профиля `NOT_CONFIGURED`. Не меняйте эту отметку на CONNECTED только после клонирования.

## 5. Передача результата

Один Issue — одна работа. Указывайте текущие source/contract SHA, команды и PASS/FAIL/NOT_RUN, PR и ограничения. Не закрывайте автоматически YouGile, не сливайте PR. Смежный вопрос передайте координатору ссылкой; не запускайте самоподдерживающуюся переписку агентов.

План подключения: read-only connection_check → сверка конкретного контракта → отдельное разрешённое изменение → контрактные проверки → отдельная сборка/настоящий E2E. Шаги не запускаются автоматически.

Справка: [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [skills](https://learn.chatgpt.com/docs/build-skills). Это механизм чтения инструкций; наш обмен через Issues определяется docs/exchange.md.
